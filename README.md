# mily

Пайплайн футбольных эдитов под TikTok: скачать исходники → нарезать моменты →
размножить каждую нарезку в пачку непохожих вариантов.

## Зачем

Готовые сценпаки — общий склад: одни и те же кадры лежат у всех, TikTok видит
дубликаты и режет охваты. Плюс паков по свежим событиям просто не существует —
пока их соберут, момент уйдёт.

Поэтому здесь другая схема: режем сами из полных матчей, а дальше из одной
нарезки собираем N версий с разным цветокором, кропом, скоростью и зерном.
Одна нарезка кормит всю сетку аккаунтов, и для фингерпринта это разные видео.

## Установка

```bash
pip install -r requirements.txt
```

Нужны `ffmpeg` и `ffprobe` в PATH:

```bash
brew install ffmpeg      # macOS
apt install ffmpeg       # Debian/Ubuntu
```

## Как гонять

**1. Скачать исходники.** Прописать ссылки в `config/sources.yaml`, потом:

```bash
python -m mily fetch                       # весь конфиг
python -m mily fetch --only wc26_final_esp_arg
python -m mily fetch --url "https://..."   # разовая ссылка
```

**2. Разметить моменты.** Проехать по матчу, выписать тайминги в
`config/marks.yaml`, потом:

```bash
python -m mily cut
python -m mily cut --player messi
```

Полчаса разметки дают библиотеку на неделю постинга.

**3. Размножить.**

```bash
python -m mily variate -n 10
python -m mily variate -n 10 --glob "messi_*.mp4" --audio track.m4a
python -m mily variate -n 10 --seed 42
```

Результат в `out/<клип>/v00.mp4 … vNN.mp4` плюс `manifest.json` с параметрами
каждого варианта — по нему всегда видно, что именно ушло на какой аккаунт.

**Посмотреть параметры без рендера:**

```bash
python -m mily plan -n 5
```

## Что именно рандомизируется

| Параметр | Диапазон |
|---|---|
| скорость | 0.92–1.08 |
| зум-кроп | 80–96% кадра, со смещением |
| яркость / контраст / насыщенность / гамма | ± |
| сплит-тон (тени и света раздельно) | ± |
| сдвиг оттенка | ±8° |
| резкость | 0.3–1.2 |
| зерно | 3–13 |
| виньетка | вкл/выкл |
| подрезка начала и конца | 0–0.45 с |
| crf | 18–23 |

Плюс метаданные вычищаются полностью (`-map_metadata -1`) — одинаковые теги
на всей сетке это лишний общий след.

Параметры детерминированы по `(seed, имя клипа, индекс)`: один и тот же вызов
всегда даёт тот же результат, прогон воспроизводится.

## Структура

```
config/sources.yaml   ссылки на исходники
config/marks.yaml     таймкоды моментов
clips/raw/            скачанное (в гит не идёт)
clips/cut/            нарезки
out/                  готовые варианты + манифесты
mily/                 код
```

## Оригинальная анимация

Отдельная ветка пайплайна: не резать чужое, а генерировать своё. Снимает
разом копирайт, Content ID и запрет на монетизацию переиспользованного.

```bash
python -m mily anim prompt --scenes 8   # заготовка запроса на раскадровку
python -m mily anim shots               # brief.yaml -> config/shots.json
python -m mily anim assemble            # -> out/assemble.jsx для After Effects
```

Порядок работы:

1. Заполнить `config/brief.yaml` — формат, персонаж, стиль, тон.
2. `anim prompt` даёт готовый запрос на раскадровку; ответ вернуть в `brief.yaml`.
3. Сгенерировать сцены по промптам, файлы сложить в `clips/anim/`,
   имена проставить в поле `file` у каждой сцены.
4. `anim assemble` собирает ExtendScript: композиция 1080x1920, сцены встык
   по таймингу, вписывание в кадр, подписи, перекрытия на стыках.
5. В After Effects: File > Scripts > Run Script File.

Скрипт генерируется чистым ASCII — кириллица экранируется в `\uXXXX`,
иначе ExtendScript ломает подписи на кодировке.

Один и тот же персонаж из ролика в ролик — это и есть формат. Разовые
красивые ролики не собирают аудиторию, узнаваемый герой собирает.

## Финишный проход

Генерация выдаёт себя не сюжетом, а фактурой: слишком чистый кадр, гладкая
камера, ровный свет, отсутствие оптических дефектов. Глаз читает это за долю
секунды, даже когда зритель не может объяснить, что не так.

```bash
python -m mily finish clips/anim --preset medium
python -m mily finish scene.mp4 --preset light --out out/finished
```

Проход возвращает картинке физику оптики:

| приём | зачем |
|---|---|
| плёночная S-кривая | уплотнить тени, скатить света |
| сплит-тон | тени в холод, света в тепло |
| хроматическая аберрация | каналы реальной оптики не сходятся идеально |
| ореол на светах | света растекаются по кадру |
| дрожание кадра | у генерации камера неестественно гладкая |
| расфокусировка | генерация держит резким весь кадр |
| виньетка | падение света к краям |
| подъём чёрного | плёнка не даёт абсолютного нуля нигде |
| зерно | фактура поверх стерильной картинки |

Порядок важен: подъём чёрного идёт **после** виньетки, иначе она давит углы
обратно в ноль. Зерно последним, иначе его размывают предыдущие фильтры.

Пресеты `light` / `medium` / `heavy`. Замер на тестовом кадре, medium:
минимальная яркость 10 → 12, максимальная 224 → 211, средняя 66 → 65.
То есть тени подняты, света скатились, экспозиция сохранена.

Проход тяжёлый: около 20-27 секунд на 4 секунды вертикали 1080x1920 на
слабом CPU. Ореол считается на уменьшенной копии, иначе было бы вдвое
дольше. Возврат размера идёт через `scale2ref` — обычный `scale=iw*4`
не восстанавливает сторону, не кратную четырём, и `blend` падает.

## Баннер

```bash
python -m mily brand out/finished --image banner.png
python -m mily brand clip.mp4 --image banner.png --position lower-third
```

У вертикальных лент интерфейс площадки перекрывает часть кадра, и всё,
что туда попало, зритель не увидит. Модуль считает безопасные поля от
размеров ролика:

| зона | доля | что там |
|---|---|---|
| справа | 22% | лайк, коммент, шер, звук |
| снизу | 18% | подпись, ник, музыка |
| сверху | 10% | поиск, вкладки |

Позиции: `top-left`, `top-center`, `upper-third`, `center`, `lower-third`.

Без `--position` позиция, размер, прозрачность и проявление разводятся по
роликам детерминированно от имени файла. Один и тот же баннер в одной точке
на всех роликах — это подпись сетки.

Координаты считаются числами, а не выражениями ffmpeg: запятая внутри
`min()` парсится как разделитель фильтров и разносит весь граф.

## Баннер кампании

Отдельно от `brand`: там статичная картинка в углу, тут анимация со звуком
в середине ролика на четверть экрана. Разные требования — разные модули.

```bash
python -m mily promo clips/ready --banner promo.mp4
python -m mily promo clip.mp4 --banner promo.mp4 --area 0.27 --speed 1.2
```

Зашитые правила:

| правило | как проверяется |
|---|---|
| баннер строго в середине | точка вставки считается от длины ролика |
| 1 баннер на каждую минуту | ролик делится на отрезки, баннер в середину каждого |
| не меньше 25% площади | размер считается по площади, не по ширине |
| обязательно со звуком | дорожка баннера подмешивается на каждой вставке |
| ускорение не больше 1.2x | отказ при превышении |
| ролик не короче 10 секунд | отказ при коротком |

**Площадь считается как площадь.** Баннер пропорции шире 2.25:1 не способен
занять четверть кадра 1080x1920 даже растянутый во всю ширину — предел для
такой пропорции около 15%. Модуль это ловит и говорит, какой ассет нужен.
Если запрошенная доля не влезает, размер прижимается к максимальному и
проходит, пока не опускается ниже минимума кампании.

Запятые внутри `between()` экранируются: в `filter_complex` запятая это
разделитель фильтров, и неэкранированная разносит весь граф.

## Учёт сетки

```bash
python -m mily ledger account --name phone01 --device Samsung-1 --proxy mob-1
python -m mily ledger post    --name phone01 --video clip.mp4
python -m mily ledger views   --id 4 --value 640000
python -m mily ledger due                       # что горит по окну выплаты
python -m mily ledger claim   --id 4 --value 960
python -m mily ledger ban     --name phone03    # аккаунт умер
python -m mily ledger stats                     # отдача и срок жизни
```

Две вещи, которые он не даёт забыть.

**Окно выплаты.** Ролики старше 7 дней не принимаются, награда забирается
один раз. Значит забирать надо как можно позже внутри окна: снял на 10
тысячах — потерял те 100 тысяч, что пришли бы к седьмому дню; пропустил
окно — потерял всё. `due` сортирует по остатку времени и помечает
`ПРОСРОЧЕН` / `горит` / `скоро` / `ждёт`.

Платят за просмотры **на момент забора**, а не за итоговые. Ролик, который
дойдёт до трёх миллионов за месяц, к седьмому дню может стоить в разы
меньше — и это всё, что за него дадут.

**Срок жизни аккаунта.** Аккаунт здесь расходник: важно не то, забанят ли
его, а сколько просмотров он отдаст до бана и сколько стоит поднять новый.
`stats` считает это по факту. У забаненных срок считается до бана, иначе
мёртвые продолжали бы стареть и занижать среднюю отдачу.

## Что стоит помнить

- **Музыка ловится точнее видео.** Трек матчится мгновенно, поэтому звук
  брать только из TikTok Commercial Music Library или из уже трендящихся
  на платформе саундов.
- Горизонтальный флип ломает отпечаток сильнее всего, но переворачивает
  номера и надписи — для футбола не годится, поэтому его тут нет.
- Апскейл до 4K (Topaz, Real-ESRGAN) и интерполяция под слоу-мо
  (RIFE, DaVinci Speed Warp) пока не в пайплайне — ставятся отдельным шагом
  между `cut` и `variate`.
