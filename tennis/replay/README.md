# `tennis.replay` — первый paper replay следующего гейма

Запуск на **закрытом** raw-логе BetBoom. В публичный репозиторий лог, манифест
с игроками и выходной JSONL не добавлять.

```bash
python -m tennis.replay.betboom data/raw/CAPTURE.jsonl.gz \
  --snapshot data/ratings.json.gz \
  --manifest data/replay_matches.json \
  --out data/replay_games.jsonl \
  --method shin
```

Манифест явно сопоставляет ID матча BetBoom с двумя **проверенными** Sackmann
ID в домашнем/гостевом порядке. Дата `as_of` — начало турнира, по которому
считается приор; снимок рейтингов не должен содержать будущих результатов.

```json
{
  "12345": {
    "home_id": 101,
    "away_id": 202,
    "level": "chall",
    "surface": "Clay",
    "best_of": 3,
    "as_of": "2026-10-12"
  }
}
```

Одна выходная строка на завершённый гейм: время, счёт через сет/номер гейма,
подающий, результат, `pregame_p_hold`, `pregame_p_break`, а при активной ранней
котировке — `model_p_home_at_quote`, `market_p_home` и оба коэффициента.
`skip_reason` объясняет отсутствие пары. Вероятность рынка снимает маржу
методом Shin; `--method proportional` повторяет измерение с пропорциональным
методом. `quote_source` указывает полный снимок или согласованную пару пушей.
Время первого активного полного снимка **не равно времени изменения цены**,
поэтому для него `quote_age_s` пустой. У пары пушей возраст считается от более
раннего из двух обновлений (не более 0,25 с).

Модель сверяет каждый переход очка и перестаёт оценивать матч после скачка
счёта, неизвестного подающего, сбоя часов или длинного разрыва записи. Её
ранний прогноз интегрирует два исхода предыдущего гейма по калиброванной
вероятности текущего гейма на 0:0. Котировки, впервые увиденные после его
первого очка, пропускаются: у `p_hold_now` пока нет отдельной fitted
калибровки. Переход через конец сета и тай-брейк также не оцениваются.

Для `newsletters_stake` оба исхода должны обновиться в пределах 0,25 с при
одном и том же счёте. Одиночный пуш не склеивается со старым вторым исходом;
это сознательно пропускает часть настоящих котировок. Полный снимок с двумя
активными исходами остаётся отдельным допустимым источником. В первом
46-минутном фрагменте это не изменило 8 сопоставленных геймов.
Каждый файл/запуск обрабатывается отдельно; длинные дни требуют сопоставления
и удаления повторов при объединении выходных файлов. Это исследовательский
вывод, без выставления ставок.

## Экспресс из точных исходов соседних геймов

`express.py` считает вероятность **всего купона**. Например, «подающий
удержит 6-й гейм после 40:40» (`hold_40`) и «подающий удержит 7-й со счётом
40:30» (`hold_30`). Счёт по очкам первого гейма на момент ставки передаётся
в `first_score` как количество выигранных очков каждой стороны: 40:30 =
`(3, 2)`. Вероятность второго исхода должна быть оценена *после того, как
первый исход состоялся*, то есть на правильном счёте и с нужным подающим.
Подставлять два независимых приора или умножать вероятности из линии нельзя.

```python
from tennis.replay.express import consecutive_exact_express

price = consecutive_exact_express(
    p_first_server=0.60,
    p_second_server_given_first=0.65,
    first_outcome="hold_40", second_outcome="hold_30",
    first_odds=4.70, second_odds=4.60,
    first_score=(0, 0),
)
```

Здесь `p_*` — вероятности взять очко на своей подаче **для конкретных игроков
и момента**, а не оценка этого примера или конкретного матча. При другом
счёте по очкам вероятность первого исхода может резко измениться. Формулы
предполагают обычный гейм с преимуществом и одинаковый `p` на каждом будущем
очке данного гейма. Текущий fitted `hold_v1` обучен для мужского Challenger;
женские матчи из скриншотов нельзя объявлять им оценёнными. Автоматического
разбора точных исходов из BetBoom в replay пока нет.
